# Test Documentation Policy · `rec:testdocs:documentation-policy`

**Status:** Decided

This record defines the authored documentation that accompanies the derived test inventory. Projection files are views of live source and never become a second mint authority.

## Authored claims · `sec:testdocs:authored-claims`

**Convention (Two labels)** · `conv:testdocs:two-labels`

A test has one derived `test` label naming the executable asset and may cite one authored claim label naming the behavior it evidences. The test label is generated by the profile; the claim label is minted at an authored documentation head.

**Requirement (Carrier extension)** · `req:testdocs:carrier-extension`

Every subscribed README and documentation tree used to state test claims belongs to the owner's prose carrier. Adding a projection without carrying its authored claim source is a configuration defect, not an empty inventory.

## Projections · `sec:testdocs:projections`

**Convention (File test index)** · `conv:testdocs:file-index`

A file index is an exact generated view of tests whose standard places lie in that source file. It orders rows deterministically and displays derived labels without minting them again.

**Convention (Folder matrix)** · `conv:testdocs:folder-matrix`

A folder matrix is an exact generated view of subscribed test files beneath one declared level. Its level, README location, row order, and counts derive from the current execution plan rather than from path constants in code.

**Gate (Documentation exactness)** · `gate:testdocs:exactness`

Authored claims and derived projections pass only when live tests, citations, file indexes, folder matrices, and declared subscriptions agree without stale or duplicate rows.
